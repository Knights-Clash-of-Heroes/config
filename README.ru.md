# @kcoh/config

🇺🇸 [English](./README.md) · 🇧🇷 [Português](./README.pt-br.md) · 🇷🇺 Русский

Этот репозиторий содержит основную конфигурацию игры **Knights: Clash of Heroes (KCOH)**, известной в России как «Рыцарская битва героев». Он служит «источником истины» для всех статических данных игры, позволяя серверам и клиентам работать с одним и тем же набором правил и определений.

> [!WARNING]
> **`initial_state.json` несовместим с оригинальной игрой.** Его формат был разработан с нуля, а разработчики нашли оригинальные файлы игры только сейчас, почти через 5 лет после её закрытия. Оригинальный клиент не использует этот формат: он получает от сервера ответ `initialize`, разбитый на блоки. Считайте файл черновиком, пока он не будет перенесён на новый формат. Подробности в [docs/ru/initial-state.md](./docs/ru/initial-state.md).

## 🎯 Назначение

Проект ориентирован на данные. Главный файл — `config.json`: его нужно передавать игровым серверам, чтобы они, в свою очередь, раздавали конфигурацию своим клиентам.

- **Для игры**: определяет характеристики юнитов, стоимость строительства, уровни, награды и многое другое.
- **Для серверов**: служит контрактом данных, позволяя кастомным серверам создавать собственные версии конфигурации в рамках одной и той же схемы.
- **Для мейнтейнеров**: предоставляет инструменты валидации и документацию, чтобы новые сущности и изменения баланса не нарушали целостность системы.

## 🏗️ Структура репозитория

- **`config.json`**: все реальные данные игры.
- **`initial_state.json`**: начальное состояние королевства нового игрока (ресурсы, здания, участки земли и юниты). ⚠️ Устаревший черновой формат, несовместимый с оригинальной игрой (см. предупреждение выше).
- **`src/schemas/`**: схемы [Zod](https://zod.dev), описывающие формат `config.json` и `initial_state.json`.
- **`src/validation.ts`**: проверка по схемам и ссылочной целостности (id, указывающие на несуществующие сущности).
- **`src/validate.ts`**: точка входа командной строки, проверяющая оба JSON-файла.
- **`docs/`**: подробная документация по каждому интерфейсу, перечислению и структуре конфигурации на [английском](./docs/en/config.md), [португальском](./docs/pt-br/config.md) и [русском](./docs/ru/config.md) языках.

## 🛠️ Как вносить изменения

1. **Изменение данных**: правки баланса и новые сущности добавляются прямо в `config.json` (или `initial_state.json`).
2. **Валидация**: после изменения JSON запустите `npm run validate`. Команда проверяет, что файлы соответствуют схемам из `src/schemas` и что каждый указанный id существует.
3. **Документация**: при добавлении свойства или изменении интерфейса обновите документацию в `docs/en`, `docs/pt-br` и `docs/ru`.

### Скрипты

| Команда                | Описание                                                  |
| ---------------------- | --------------------------------------------------------- |
| `npm run validate`     | Проверяет `config.json` и `initial_state.json`            |
| `npm run lint`         | Запускает ESLint и исправляет, что возможно               |
| `npm run lint:check`   | Запускает ESLint без изменения файлов                     |
| `npm run format`       | Форматирует код с помощью Prettier                        |
| `npm run format:check` | Проверяет форматирование без изменения файлов             |
| `npm run typecheck`    | Проверяет типы с помощью TypeScript                       |
| `npm test`             | Запускает тесты (Vitest)                                  |

### Автоматизация

- **Pre-commit** ([Husky](https://typicode.github.io/husky) + [lint-staged](https://github.com/lint-staged/lint-staged)): форматирует и линтит staged-файлы `.ts` и проверяет JSON-файлы перед каждым коммитом.
- **GitHub Actions** (`.github/workflows/validate.yml`): при каждом push в `main` и каждом pull request проверяет JSON-файлы и запускает форматирование, линтер, проверку типов и тесты.
- **Dependabot** (`.github/dependabot.yml`): раз в неделю проверяет обновления npm-зависимостей и GitHub Actions.

## ⚠️ Отказ от ответственности

Проект независим и не связан с Playkot. Он полностью **открыт** (open-source) и **некоммерческий**.

Репозиторий создан фанатами с целью сохранить наследие игры и углубить знания в разработке игр. Проект затрагивает реальные технические задачи: архитектуру, паттерны проектирования, WebSocket и системы, управляемые данными. Мы ни в коем случае не стремимся навредить Playkot или правообладателям оригинала; это технологическая и образовательная дань уважения.
